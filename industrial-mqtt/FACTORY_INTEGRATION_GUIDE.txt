## 3. Step-by-Step Installation & Setup

### 3.1 Installing Mosquitto Broker
* **Ubuntu/Debian:** `sudo apt update && sudo apt install mosquitto mosquitto-clients`
* **Arch Linux:** `sudo pacman -S mosquitto`
* **Run in background:**
  ```bash
  /usr/bin/mosquitto -d
  ```
* **Verify running:**
  ```bash
  ss -tlpn | grep 1883
  ```

### 3.2 Setting up PostgreSQL (Local Port 5434)
We run PostgreSQL with its data directory inside the workspace and unix sockets in `/tmp`:
```bash
# Start PostgreSQL server
/usr/bin/postgres -D /home/darshan/Projects/Work/TCC/Exploration/industrial-mqtt/db_data &
```

### 3.3 Installing & Starting Ignition Gateway
1. Download the Linux 64-bit installer or ZIP from [Inductive Automation](https://inductiveautomation.com/downloads/).
2. Extract to your desired folder (e.g., `/home/darshan/ignition textmode=true/`).
3. Start the Gateway in console mode:
   ```bash
   "/home/darshan/ignition textmode=true/ignition.sh" console &
   ```
4. Open your web browser and navigate to:
   **[http://localhost:8088](http://localhost:8088)**
5. Follow the commissioning wizard:
   - Select **Maker Edition** (for personal learning) or **Standard Trial Edition**.
   - Create an admin user account (e.g., username `admin`, and your chosen password).
   - Complete setup and click **Start Gateway**.

## 4. How to Download & Install MQTT Modules (Plugins) in Ignition

Ignition uses a modular architecture. Out of the box, Ignition does not speak Sparkplug B until you install the **Cirrus Link MQTT Engine** module.

### 4.1 Step 1: Download the Module Files
1. Visit the [Cirrus Link Module Downloads page](https://sales.cirrus-link.com/download-modules/).
2. Download the `.modl` file matching your Ignition version (e.g. `MQTT-Engine-signed.modl`).
3. Keep the `.modl` file in your Downloads or project folder.

### 4.2 Step 2: Upload into Ignition Gateway
1. Open your browser to **[http://localhost:8088](http://localhost:8088)**.
2. In the left navigation menu, expand **Config** and go to **System ➔ Modules**.
3. Scroll to the bottom of the page and find the section:
   **"Install or Upgrade a Module"**.
4. Click **Choose File** (or Browse) and select your downloaded `MQTT-Engine-signed.modl`.
5. Click **Install**.
6. The browser will display the Cirrus Link Certificate and EULA agreement. Check **"I accept the terms..."** and click **Confirm**.
7. Once installed, verify that **MQTT Engine** appears in the module list with a green status: **Running**.

### 4.3 Step 3: Connect MQTT Engine to Mosquitto
Now that the module is installed, tell it where your MQTT broker is:
1. In the left navigation menu under **Config**, scroll down to find the **MQTT ENGINE** section.
2. Click **Settings ➔ Servers**.
3. Click the link: **Create new MQTT Server**.
4. Configure the server connection settings:
   - **Name**: `LocalMosquitto`
   - **URL**: `tcp://localhost:1883` *(pointing to our local Mosquitto)*
   - **SSL**: Leave unchecked (local unencrypted testing)
   - **Username / Password**: Leave blank (unless you configured Mosquitto passwords)
5. Click **Save Changes**.
6. The status in the table should now show **Connected** with a green checkmark.

## 6. How to Build Visual Gauges & Dashboards in Designer

### 6.1 Creating a Perspective View (HMI / Mobile View)
1. In the **Project Browser** (top left), expand **Perspective ➔ Views**.
2. Right-click on **Views** ➔ select **New View...**.
3. Name the view `Machine_Overview`.
4. Layout type: Select **Flex** or **Coordinate** ➔ Click **Create View**.

### 6.2 Binding a Live Gauge to Machine Telemetry
1. On the right side of the screen, open the **Component Palette**.
2. Find the **Gauge** component and drag it onto your view canvas.
3. With the Gauge selected, look at the **PROPS** panel on the bottom-right.
4. Locate the `value` property (defaults to something like `50`).
5. Hover over `value` and click the small **Link / Binding icon** that appears next to it.
6. In the binding popup:
   - Select **Tag** on the left.
   - Click the folder browse icon and navigate to:
     `[MQTT Engine]Edge Nodes/Plant1/Line1/Machine01_Stamping/Hydraulic_Pressure_Bar`
   - Click **OK**.
7. In the Gauge PROPS:
   - Change `minValue` to `0`.
   - Change `maxValue` to `250`.
   - Change `units` to `Bar`.
8. The gauge needle will immediately start animating in real-time, matching the pressure simulated in your Python script.

### 6.3 Creating a Running/Stopped Status Indicator
1. Drag a **Label** component onto the canvas above the gauge.
2. Select the Label ➔ go to PROPS ➔ `text`.
3. Click the **Binding icon** next to `text`:
   - Select **Tag** ➔ choose `.../Machine01_Stamping/Status`.
   - Under **Transform**, click **Add Transform** ➔ select **Map**.
   - Set: `0` ➔ `"STOPPED / FAULT"`, `1` ➔ `"RUNNING"`.
4. Click **OK**. The label now dynamically shows whether the machine is operating or stopped.

## 7. How the Code Works & How Parameters Map to the Screen

Here is the exact lifecycle of how a value moves from a line of Python code to your physical screen:

```mermaid
sequenceDiagram
    autonumber
    participant Py as Python Simulator (sparkplug_factory.py)
    participant Mosq as Mosquitto Broker (:1883)
    participant Eng as Ignition MQTT Engine
    participant Des as Ignition Perspective Gauge
    participant BE as FastAPI Backend & PostgreSQL

    Py->>Py: state["hydraulic_pressure"] = round(random.uniform(175.0, 195.0), 1) -> 184.2
    Py->>Mosq: Publish DDATA (Binary Protobuf: Hydraulic_Pressure_Bar = 184.2)
    Mosq->>Eng: Forwards MQTT packet to Ignition
    Eng->>Eng: Unpacks Protobuf & updates tag [MQTT Engine].../Hydraulic_Pressure_Bar
    Eng->>Des: Fires tag change event over internal WebSocket
    Des->>Des: Gauge needle animates to 184.2 Bar on screen!

    Note over Py,BE: Simultaneously in our Backend Pipeline:
    Py->>Mosq: JSON payload {machine_id: "M01", hydraulic_pressure: 184.2}
    Mosq->>BE: Async MQTT subscriber receives JSON
    BE->>BE: Normalizes, validates & stores in PostgreSQL (JSONB parameters)
    BE->>BE: Broadcasts to mobile app via WebSocket /api/v1/ws/live
```

### Direct Code Mapping

In [simulator/sparkplug_factory.py](file:///home/darshan/Projects/Work/TCC/Exploration/industrial-mqtt/simulator/sparkplug_factory.py):
```python
# 1. Parameter definition in Python
metrics = [
    m("Hydraulic_Pressure_Bar", DataType.FLOAT, state["hydraulic_pressure"]),
    m("Die_Temperature_C",      DataType.FLOAT, state["die_temp"]),
    m("Stroke_Count",           DataType.INT64, state["stroke_count"]),
]
```
1. **Parameter Name (`"Hydraulic_Pressure_Bar"`)**: Becomes the exact tag name displayed in Ignition's Tag Browser.
2. **Data Type (`DataType.FLOAT`)**: Informs Ignition and PostgreSQL that this tag is a floating-point number, enabling analog gauge scaling.
3. **Value Calculation (`random.uniform(175.0, 195.0)`)**: Simulates the physical behavior of hydraulic pumps cycling under load.
4. **Transport**: `edge_node.update_device(...)` serializes the data into compact Sparkplug B binary protobuf bytes and delivers it across Mosquitto.
